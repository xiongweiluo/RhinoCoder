## 真实环境演练

### 停止后不再产生新工具调用

运行一个严格串行的多步任务，任务已完成 6 次工具调用并再次进入规划阶段时点击“停止”：

1. UI 显示“停止请求已发送；Agent 将不再发起新的工具调用”。
2. 终态为 `cancelled`，终止事件为 `run.cancelled`。
3. 点击停止时 `tool.started = 6`、`tool.completed = 6`。
4. 继续观察 2 秒后，两项计数仍为 6。

因此取消信号生效后没有启动新的工具调用。

### Undo

1. 运行只允许 `create_sphere(radius=4.5)` 与闭环场景检查的任务。
2. Scene Summary 显示新对象尺寸 9×9×9、中心 (0,0,0)，场景对象数 28→29。
3. 点击 Undo 后 UI 显示完成回执并自动刷新 Scene Summary。
4. 场景对象数 29→28，9×9×9 目标对象消失。

首次演练暴露了 Listener 写操作未进入 Rhino Undo 栈的问题。修复方式是在 Rhino 主线程执行每个变更类操作时调用 `BeginUndoRecord` / `EndUndoRecord`；查询、Undo 自身与评测清场不创建事务。单元测试覆盖成功、查询排除和异常关闭三条路径。

### 任务级精准回滚

1. 单次任务创建半径 5.5 的球体及 13×15×17 方块。
2. Scene Summary 显示场景对象数 28→30，任务结果记录两个创建对象 GUID。
3. 点击“精准回滚”后 `delete_objects` 返回删除 2 个对象。
4. Scene Summary 自动刷新为 28 个对象，两个目标对象均消失。
5. 当前任务历史记录标记为已回滚，按钮自动禁用。

### 三类反馈

依次提交正确、部分正确和错误反馈：

- 每次提交都收到“反馈已保存”回执。
- UI 历史状态显示三类已记录反馈。
- 本地 JSONL 尾部标签依次为 `accepted`、`partial`、`rejected`。

反馈文件属于本地运行数据，不提交 Git。

## 本轮实现

- 统一 `control.completed` 控制回执，停止、Undo、回滚和反馈均显示可理解结果。
- Undo 和精准回滚后自动刷新 Scene Summary，并同步任务历史快照；同一任务的 Undo 与精准回滚均防止重复提交。
- 运行中、可重试、可回滚、可反馈等按钮按任务状态启用或禁用。
- 精准回滚记录完成状态，防止重复删除。
- 反馈只允许对已结束任务提交，并在任务历史中恢复显示状态。
- Listener 为每个变更类操作建立 Rhino Undo 事务。
