## 已实现的有限交付

新开发身份 `C5DEV-REUSE-20261011-A` 与协议 `c5-reuse-field-development-v1` 独立于旧 D、旧正式 study 和新正式候选。`c5_reuse_field_scope` 只核对传入的 spec/runtime/本人批准记录，拒绝旧身份、私题、自动重试、产品路由改变、缺失宿主接受及预算越界；它不证明记录的批准来源，也不验证完整现场执行权限。测试中的 ready/grant 仅为合成记录，未在实际环境建立。

- `plugin/rhino_listener/c5_reuse_admission.py` 在冻结的持久准入目录中，先持久化永久 O_EXCL tombstone，再提交 SQLite。崩溃间隙永久禁止新效果；换 state 或 runtime 不解锁同一 study/role。独立锁文件避免 macOS SQLite 锁冲突。它是**每个固定端点命名空间**的准入基础，不是跨主机事务，也不能阻止调用者另选准入目录；实际可信入口必须固定两个端点的持久命名空间。
- `training/c5_reuse_field_journal.py` 保留有界、不可覆盖的原始行，发布后读回，核对目录身份和前一行；独立只读磁盘读取核查完整人口、权限、硬链接、非普通文件、链与外部给定 head。每条实际发布受既有通道 1 MiB 限制，累计最多 64 MiB、4096 行。哈希一致不证明外部锚来源。
- `training/c5_reuse_generation.py` 在调用提供者前持久化请求与每个生成阶段意图，保留返回文本的原始 UTF-8 字节；无效元数据、超长文本、未知生成、源码/预算/完整时序失败永久退休。超长返回保留前262144字节、实际长度和截断标记，不能认证完整返回。原 selector→invoker、system/schema/parser、23目录/12工具和解码预算直接复用未改动代码；本模块仅接受注入的 tokenizer/route/generate，**尚无真实加载器或现场入口**。
- `training/c5_reuse_generation_audit.py` 不导入生成生产者；从原始行独立复算意图、原始文本、返回、请求顺序和原契约提示/解析语义。无完整 plan/tokenizer/最终 head、空记录、未知或缺项不能取得完整 coverage。实际物理生成总量仍不被这个 reducer 独立证明。
- `plugin/rhino_listener/c5_reuse_host_session.py` 绑定新身份，沿用有限观察器，准入先于订阅，保留 normal2048/cleanup256/journal4096；Python3.9导入不触发 training/model/CLR。测试只用 CPU 替身，**真实 entry-return/Idle、warmup、外部准备/最终锚和当前宿主验收尚未接线**。
- `training/c5_reuse_stop.py` 提供目标 PID/UID/boot/start tick/映像/argv/cwd 精确绑定、单次 pidfd SIGTERM 和有限等待，不枚举或按名称杀进程，不重试或升级信号。未知仍消费独立 stop 准入。目标专属批准与现场子进程创建/预声明停止政策尚须完整入口设计；没有向实际进程发送信号。
- `training/c5_reuse_development_plan.py` 只读原公开 D spec 的固定字节，抽取已被本人排除的四家族/八交叉槽原文、顺序和许可上限。不读私有 train/正式题，不新增语义家族，不重激活旧 D，也不冒充新的泄漏独立证明。

这些组件需要完整可信入口验证当前字节、资源、人工批准来源和双方准入后才能使用。它们不会自行加载模型、订阅 Rhino 或创建正式 run；CPU 对注入替身的成功不能当现场门 PASS。
