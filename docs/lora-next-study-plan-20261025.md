### 离线多步/恢复好，为什么现场仍失败

1. **测量对象不同。** 离线8/8与8/8使用事前给定步骤上下文，评测结构化输出；真实任务每步依赖自身上一步实际结果和场景变化。离线结果没有证明自主分解、识别已完成子目标或处理执行反馈。[离线报告](c5-final-evaluation-report.md)
2. **输入契约存在可检验差异。** 当前main的[复用runner](../training/c5_formal_reuse_runner.py)每步传相同`task_text`和实时`semantic(scene)`；[step_input](../training/c5_rhino_adapter.py)渲染原任务与unit/objects/groups，不显式携带前一动作、执行回执、错误或剩余目标；[生成入口](../training/c5_reuse_generation.py)沿此路径构造输入。场景有反馈价值，但不保证足以消除多步歧义。静态实现是线索；实际各失败prompt包含什么仍需所有者从已存证据返回字段级核实。
3. **“恢复”也有范围差异。** [任务契约](../training/c5_formal20_plan.py)的error_recovery是任务中描述的预存错误状态，不等同于遇到任意运行异常后自动恢复。下一开发设计应分别测试“修正已有错误”和“对可信执行失败反馈作决策”，不能混为同一指标。
4. **执行与评分有独立约束。** 当前max_steps等于冻结expected_operations长度、读写额度与预期计数绑定；模型输入不包含预期答案。多余/错误类别动作可触发正确拦截。必须核实合法任务是否能在该预算内完成，不能为失败放宽旧额度。新研究若采用任务级公开预算/停止标记，属于共同契约变更，先开发验证、再事前冻结。
5. **样本与干扰不同。** 现场每类只有2题，多步其中一题遭工程阻断，不能用0/2推断所有多步能力为零。F03/F13的调用未派发信号与policy denial一致；F15/F16没有该信号，也不自动证明派发/读回绝无问题。

### 严格解析改善，为什么仍未完成任务

四个任务失败parse均true，说明格式层改善；仍要依次满足“正确决定是否调用→正确工具/参数/顺序→授权→实际派发→真实状态满足目标→证据完整”。[评分器](../training/c5_formal20_scorer.py)中arguments_exact依赖tool_name_exact，sequence还依赖完整回执与读结果；这些false并非独立根因。F13几何通过但决策失败尤其说明最终场景与任务契约需分别核实。三项工程失败的解析指标为null，不能从全表没有strict_parse_failed推出LoRA每次都完成了解析。

- `first_divergence_step`：零起始或unknown；`earliest_layer`：fixture/context/selection/arguments/policy/dispatch/readback/scoring/unknown；说明先后关系是否有证据。
- F04/F18：`fixture_mismatch_class`限单位、对象数、别名、属性、几何断言、读回稳定性、预期定义、未知；是否稳定复现于**原记录**，是否已证明在模型前阻断。不要为了回答重跑。

| 控制器/原生语义不一致、许可额度无法表达合法任务 | 修控制器，明确公开任务预算、完成/弃权语义、反馈与调用的边界 | 模型输出到签名载荷及回读逐项对应；越权、漂移、重复和未知回执都拒绝；不能只测成功路径 | 通常否；若修改模型可见输出语法则是新契约，需训练兼容性证据 |
| 共同链/输入充分且独立开发仍稳定出现语义错误 | 定向补同机制但非旧题改数字的训练家族：多步进度、状态条件动作、歧义/充分信息成对案例、预存错误修正 | 全家族隔离、来源审计、人工标签核实，覆盖误用/正确拒绝；训练与推理同前缀、assistant-only label、token审计 | **可能需要**，先形成可证伪训练假设和最小试验包 |
| 合法等价计划被exact评分拒绝 | 先独立审查任务定义/评分器；保留历史评分，将问题当新研究设计缺陷 | 新任务在冻结前验证期望规则；主指标保留共同严格契约，任务有效性另列次指标。若另选语义主指标，须在新集生成/冻结前重新预注册全部三路相同规则 | 不用训练逼模型记住任意答案路径，也不按已见结果修改评分 |
| 仍不能区分上述原因 | 保留unknown，完成所有者最小补证和公开合成诊断设计 | 每项具备“证据→首次偏离→待检验假设→一项最小反证”，或明确缺口使哪一决策不可作出 | 不训练，不增加epoch |

允许进入训练准备的必要证据：①关键夹具/派发/评分缺陷已排除或修复并有独立开发验证；②候选输入在运行时可获得、无gold泄漏；③在至少两个独立开发家族上复现相同剩余语义错误，而不是只看旧7项；④数据覆盖审计发现与该错误机制对应的缺口，且标注通过；⑤冻结一个假设、一个候选数据版本/训练配置、选模规则及预算。上述条件必要但不保证训练有效。

建议首个训练候选保留原基座与可比LoRA容量，优先改变**经诊断支持的数据/契约因素**，不同时扫rank、学习率、epoch和提示词。新adapter从同一基座初始化，当前checkpoint132保留为不可变对照；若改用继续训练，须单独说明为何以及对应控制。最多一个候选训练run，checkpoint只按独立validation选择，开发集只作门槛验收，不用最终集或旧20题选checkpoint。若validation显示无增益或关键行为退化，停止候选，不为凑第三臂重训。

若工程/反馈优化已足够或训练依据不足，走**不训练分支**：比较基座与当前LoRA在共同新链上的表现，明确没有“新LoRA”。工程/提示变化是系统改进，不能归为权重效应。需三路时，只有通过上述门的候选权重才作为第三臂。

## 5. 下一轮公平比较草案

### 研究问题、隔离和三路控制

主问题：在同一个已冻结执行链与评分器上，新LoRA是否比当前checkpoint132提高端到端成功率？基座为参照。基座、当前LoRA、新LoRA使用同一基座revision/量化/tokenizer、相同工具范围与schema、输入渲染、场景摘要、反馈字段、解码和输出上限、每任务步数/读写额度、许可/派发/回读/清理/审计规则。唯一权重差异是adapter关闭、当前adapter、候选adapter；禁止一条路线额外修输出或多次生成取最好。

- **诊断开发区**：原20题匿名证据与获准的机制分析均作开发用途，隔离标签只追加；新合成开发家族由通用机制定义，不复制私题。另分训练、validation及独立开发验收家族；同模板改数字不能跨分区。模型/prompt选择在validation内，独立开发验收被用于调参后必须登记为已用，不再称独立。
- **最终区**：候选模型、共同链、工具范围、评分、样本规划、排除规则全部选定后，才由所有者独立保管新冻结集；本次不生成/接触它。以语义/模板/来源家族隔离，覆盖原20、原80、A5/P2、历史及新训练/validation/dev；保管人返回排除审计摘要和不可变承诺，不向代理传题/答案/私有哈希。不能证明隔离就不得称独立最终测试。
- **相同起点，不强行相同后续prompt**：每题三路分别重置等价夹具，模型前验证相同初始语义输入。后续只能使用各路自身真实结果；不把另一模型轨迹或标准答案交给它。三路顺序按题预先均衡随机，冻结seed；控制温度/缓存/adapter切换和场景残留。原现场两路硬编码、20题固定scorer不能直接拿来跑三路，需新研究命名空间/三路适配与独立验证，保留旧入口原字节与消费屏障。
- **开发消融**：在新开发区用相同权重比较旧/新反馈输入，先隔离工程和上下文收益；正式三路均用同一选定链。所有候选开发尝试和选择规则公开登记，不能给新LoRA额外测试预算或以最终集挑prompt。

### 建议规模、指标与事前门槛

建议先按**40个新独立家族、每家族1题、三路120槽**做预算和精度论证：核心12（每工具1，覆盖而非工具级可靠性估计）、多步8、恢复8、澄清6、拒绝6。类别配额在生成任何新测试题前决定，不按旧失败挑有利题；这是一个明确偏重多步/恢复的目标分布，不能代表所有真实用户请求。最终数量须由开发不一致对比例与所需最小效应做功效/精度审查；不能声称40题自动足够。若预算不足以支持确认性研究，在曝光前将整轮定为探索性报告，不能看结果后追加题或改成“已证实提升”。

| 口径 | 预注册建议 |
| --- | --- |
| 主指标 | 每路线“证据核实的端到端成功数 / 冻结N”。成功要求正确决策/严格调用序列、最终几何/属性/只读结果和非目标保护、完整审核及清理，统一给三路。澄清/拒绝任务需正确不调用；不能以无副作用自动算任务成功 |
| 失败核算 | 全N分别列成功、任务失败、工程失败、证据未知、未尝试，互斥主分类加可重叠诊断标签。工程失败/未知/未尝试不增加成功分子也不缩小分母；原scored_success=null不改成能力零分。报告尝试覆盖和工程失败率，冻结多原因优先级；无法归因列unknown |
| 次指标 | parse/name/arguments/sequence、任务有效性、各类别成功率、合法调用到实际派发比、回读一致性、错误/安全拒绝、延迟p50/p95、tokens与GPU驻留。可另报共同无工程干扰子集的诊断结果，但不能替代全N主指标或用各路不同分母比较 |
| 工程完整门 | 全部routes×N槽（三路40题时为120槽）的最终状态/证据/清理可核实，未知或未尝试0；重大安全错误、重复写、未核实清理0；建议每路线工程失败率≤5%（N=40时≤2）。任何工程失败仍留分母；超门只能报告本轮失败/局限，不能删除失败再算PASS |
| 有用改善门（建议，待本人在曝光前确认） | 新LoRA端到端≥70%，比当前LoRA提升≥10个百分点（N=40时净胜≥4）；多步+恢复合并≥50%，核心/澄清/拒绝各层观察成功数不低于当前LoRA。同一分布下比较，不与历史13/20直接相减。这些是新研究目标，不是改旧C5门槛 |
| 统计解释 | 唯一主要比较是新LoRA对当前LoRA；报告配对差、净胜、95%区间及双侧exact McNemar。确认性“提升”还需预注册统计标准（建议p<0.05且差值区间下界>0）和完整门；对基座的两组比较与类别分析为次要描述，不额外宣布未校正显著性。不训练分支将当前LoRA对基座事先设为唯一主要比较，并在新测试生成前明确该分支的效果门；它只能说明共同新链内两模型差异，不能声称新权重带来提升 |
| 无提升/不确定 | 工程合格但未达到效果/统计标准，判“未达到预注册改善标准”；样本或证据不充分则“结论不充分”。不得把它等同能力绝对无效，也不自动晋升产品或开启下一次试验 |

统计实现沿配对家族重采样，三路共用同一抽样索引；固定seed、重采样次数、分层权重与区间方法，冻结前用纯合成数据验证极端/退化情况。若保留分层配额，区间按层内家族抽样再以固定配额加权；退化区间不当作确定性证据，预先规定保守备用方法。exact McNemar使用不一致对的二项分布，参见[statsmodels官方说明](https://www.statsmodels.org/dev/generated/statsmodels.stats.contingency_tables.mcnemar.html)；配对重采样同索引原则见[SciPy官方说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)。这些方法不能消除数据泄漏、基础设施偏差或样本不足。

### 资源、一次性运行与停止规则

建议资源分期上限：规划/公开归因**0 GPU-hours**；后续独立开发模型/现场验证≤**2 GPU-hours**；条件训练及validation≤**4 GPU-hours**；最终三路比较（含加载、idle和退出导出）≤**16 GPU-hours**，合计≤**22 GPU-hours**。这是待所有者批准的封顶草案，不是已有资源或支付授权；不训练就取消训练预算、按两路80槽重算，不自动挪用结余。

进入最终冻结前必须有独立开发的时延测量与严格slot超时策略：`routes × N × T_slot_cap + 全部加载/切换上界 + 900秒退出导出预留 ≤ 阶段剩余驻留预算`，并满足实际租期的同一完整窗口。以120槽为例，若拟定420秒/槽，则槽预算14小时，剩余2小时需覆盖所有加载/切换和至少900秒导出；这是可行性示例，**尚未证明420秒适合任务或模型**。沿旧1500秒规划代理则仅槽预算50小时，16小时不可行：必须在曝光前选择更充分资源或明确缩小目标/样本并重新审查精度，不能运行到一半补预算或缩短慢模型的时间限制。每路同一时限/恢复策略，时限需依据最慢路线的开发证据确认。

费用按实际供应商报价`小时单价 × 批准租期 + 存储/传输上限`另由本人确认；GPU型号/VRAM、权重/依赖身份、可用磁盘与原始证据导出空间必须核实。租期、驻留（含idle）、模型生成时间、训练活跃时间及账单分别记录。旧历史总GPU未知仍保留，不以新预算追认旧合规；新研究账本独立追加、链回旧研究身份，不覆盖旧FIRST/消费。

事前冻结的一次最终比较：每槽一次；普通任务错误完整落盘/核实清理后继续预定顺序；**不重试失败槽、不补题、不择优、不得按中间分数早停或延长**。任何越权/重复写、身份或共同环境漂移、未知原生效果、账本/证据损坏、清理未知、预算/租期不足或本人中断，停止并保管证据。正式曝光后不修代码继续同一确认性测试；整轮作不完整研究报告，不把未尝试槽移出N。预曝光基础设施失败最多一次有界恢复、需完整零曝光/零效果证明和原预算内窗口；超过即退役，不能通过新ID清零。新测试的消费、保管人入口和一次执行须另获精确包批准。
