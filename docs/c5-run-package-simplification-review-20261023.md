## 一份运行包与一个私下入口

`reuse-formal-20261023-r2` 的 layout、policy、spec、runtime、前缀证据和代码清单绑定在同一份冻结中。材料/规则/两哈希审议不等同实际执行批准。新 grant 的执行字段默认 false；仅在另行明确授权执行且登记器显式收到 `--execution-approved` 后才可写入执行 grant、追加迁移并启用第3次加载。

实际执行另批后，安装一次冻结的 Rhino 等待队列，保管人只运行一次私下命令 `tools/c5_formal_run_package.py run`。队列观察公开的零题准备状态；不再经聊天转述“已就绪/已确认/已输入”。本人在同一终端私下填写 age/identity 路径，元数据有效后核对完整哈希和包规则、确认一次；这些输入全部发生在任何原生夹具/宿主基线准备和模型加载前。实际 ready 与终止回执随后自动展示和保管，不声称本人逐次人工见证。正式曝光消费仍在解密前持久写入原账本。

后续预曝光恢复不会伪造新的人工作证：以 `package_preload_observed` 记录自动观察，不追加冒充逐次人工确认的记录。真实终止回执自动展示并私下保存，重新计算原始连续性、签名、退出和捕获证据；保管方式明确标为 `owner_authorized_automatic_capture`，不声称逐条人工核对或新的外部密码学见证。完整正常审计直接在本人进程中执行，仅输出脱敏摘要。

队列在每次实际宿主封存前退订，在该次终止并移除原观察器后才重新等待；包结束后通过绑定 nonce 的控制回执自行退订。不能证明退订时摘要显示未知，不能宣称清理 PASS。

## 检查、停止和导出

完整模型与兼容环境检查集中在真实资格子进程加载入口；父监督器先完成完整配置/许可/身份校验而不重复扫描多 GB 模型。加载后完整性检查仍保留，避免加载期间资产变化。重复的同一次快照哈希扫描已移除。

`tools/c5_formal_reuse_control.py` 是独立停止/导出入口，静态计算并冻结其 Python 依赖闭包。它只需原完整 grant、固定公共材料、控制代码、资格身份和共享停止记录；不导入模型入口、模型加载器、Torch 或 runner，不执行模型资产/完整环境预检，不受生成预算或租期过期所阻。它不削弱 pidfd、UID/boot/start ticks/argv/executable/cwd 资格和一次信号约束。

## 规则实现的补充收口

- 新包的全部本人输入和元数据校验位于任何夹具/宿主封存之前；一次包级真实同意明确不声称逐次人工见证 ready。缺实际 ready 观察时，原账本拒绝消费加载意图。

- 控制器中断但原始 EOF、资格退出、原生终止等证据充分时，单入口可补记失败/结算并有限恢复；缺证据不写成功。缺生产方结算时单独记录由原资格退出推导的驻留观察，不伪造或覆盖生产方 settlement。
