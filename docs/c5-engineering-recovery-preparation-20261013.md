# C5 工程恢复规则修订与准备审核

2026-10-13。本人已明确授权实现/CPU验证/审核材料，新的现场执行另行批准，见[准备接受记录](../eval/c5/engineering-recovery-owner-preparation-acceptance-20261013.json)。本轮实现六个恢复组件、控制器接线及只读审核工具，不调用真实模型/Rhino、SSH、现有 pidfd 目标或全局准入入口。没有部署、现场身份、实际执行 grant、真实 retry 或新正式私题读取。

## 行为修订

| 阶段/触发 | 新行为 | 保留的边界 |
|---|---|---|
| 确认输入不匹配、取消、EOF/Ctrl+C | 模型加载前最多3次纠正；本次暂停后可重新打开确认入口，不计工程尝试 | 不替本人签署；不显示误贴密钥；不可见字符只报告码点，不静默删除 |
| 固定公开工程的启动/运输/已知原生操作失败 | 同一campaign最多3次加载尝试，保留每次原始链；确认在同一材料/宿主snapshot下复用 | 任务、模型/解码/阈值契约保持；不根据质量失败自动重跑选优 |
| 公开诊断流缺失但目标退出/已知宿主收尾/未曝光私题已独立核实 | 原始缺项明确保留，可在有限次数/共享预算内再做公开工程 | 缺失不能被拼成完整PASS，后续成功仍待独立联合审计 |
| 未知目标或宿主清理 | 暂停待独立核查，核查记录追加后续接 | 不猜PID、不重复close/stop、不清理原错误后重新计数 |
| 源码修复或实际租期修订 | 同一campaign追加新的精确批准和旧链head；清除旧确认资格，重新在加载前确认 | 不换身份清计数、不重置第一次加载预算；公共题/比较契约及旧历史不能随修订变化 |
| 正式私题曝光或正式生成意图 | 在实际访问/生成回调前持久消费，失败也保持消费 | 本组件仅提供消费门；正式40槽仍由独立本人私下入口/冻结批准控制 |
| 独立stop与监督器finally同时到达 | 同一GPU本地目标日志下串行；第一个记录一次pidfd SIGTERM/结果，后者读取结果 | 不第二次领角色或发信号；claim后崩溃保留unknown，禁止盲目补发 |

确认只承担预加载准许，未伪造一个尚不存在的worker ready。实际加载后的ready仍要由固定的独立验证actor核对原始scope/宿主/模型锚，再放行固定公开请求；省去加载后120秒再要求人工输入的易失窗口。新输入函数对普通空格/NBSP兼容，对零宽/控制字符给出码点提示，三次失败只暂停。D原输入字节未取得，不追认其具体字符原因。

## 实现接线

- policy：失败分类、有限次数、正式消费及受影响验证依赖。
- confirmation：本人TTY预加载确认及snapshot字节绑定。
- storage/controller：O_EXCL/fsync追加链、可重开状态、累计预算、精确修订批准；控制器按preflight→本人确认→持久加载意图→加载/ready独立核对→固定公开执行→每个收尾actor一次→独立审计待办接线。
- history：未来新完整批准后，在原同一global admission根的固定v3父目录初始化唯一campaign，核对A～D八份退休/封存grant及C/D旧消费文件；拒绝空历史、活动旧grant、替代根及新campaign绕过。
- stop：固定资格目标的原生pidfd接口，跨线程/进程共享首次结果。保留目标身份/父子关系/boot/argv及停止前后核验。日志claim后未知退出只能待核查，不能二次信号。

Controller没有默认GPU/Rhino/SSH actor，也不是重新开启D的入口。新现场必须将这些组件与实际固定actor、完整字节/环境/模型清单、同一根历史及独立原始联合审计纳入新的完整冻结，取得新版spec/runtime精确批准后才可登记/部署/运行。本审核包的field_actors_registered、execution_ready及execution_authority均为false；其哈希不是现场执行哈希，旧A～D批准不转移。

## 材料复用与增量验证

[只读完整准备审核包](../eval/c5/engineering-recovery-preparation-review-20261013.json)覆盖346份源文件：原337映射文件＋原D runtime＋8份新增源/测试/审核工具。原337字节、A～D失败JSON/spec/runtime/接受记录保持。新增源形成独立准备清单，不改现场已部署冻结或追写历史结论。

模型/adapter、tokenizer、兼容Python和原环境/宿主清单沿用原完整材料作为复用基准。本轮没有重新构建环境、训练/改模型或重做未受影响的模型CPU工作。历史回执只证明其采集时点，不能替代未来现场最新boot/进程/租期/实际资产字节核验；缺少可靠缓存身份时该部分仍须只读复核，不能只凭mtime或计划SHA声称新字节PASS。

本地针对retry_policy、confirmation、stop及其依赖，只运行新恢复回归和相邻旧确认/预算/资格停机控制；真实CPU子进程、双进程/八线程争停、重开/崩溃、重哈希篡改、正式曝光等均覆盖。Linux CI另以真实CPU子进程验证原生pidfd一次SIGTERM，无GPU/模型。库导入、纯review工具和CPU模拟确认不会创建现场批准或本人回执。

仓库既有push/PR CI仍执行完整发布检查；本轮不另起无必要的GPU验证，也不继承#18旧CI作为当前head证据。最终通过/跳过/耗时及日志SHA以本准备PR精确head结果为准。

## 资源、审核与下一门

每次工程重试继承第一次加载epoch、持久预算检查点和同一有限阶段上限，等待/修复/停止不返还时间；源码revision和进程重开也不归零。旧D已花时间及历史累计未知保留，不追认原16小时合规、不返还A～D旧预算，不自动续租/付款。新阶段的实际租期、完整窗口和finite cap由未来完整执行scope确定；本轮未生成新的现场资源事实。正式阶段保留原独立条件和评分门，不改NO-GO或默认混合。

本分支基于未合并的失败记录PR #18；主工作区九份WIP和main保持。仓库所有者仍是唯一必需reviewer和独立保管人；代理准备审核材料，不代批或自动merge。接下来是按新规则做一次增量现场候选适配/完整冻结与最新只读复核，实际运行再单独审议。
