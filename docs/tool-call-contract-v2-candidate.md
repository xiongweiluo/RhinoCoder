状态：**仅 CPU 合成验证通过；未预注册、未接入产品或 C0–C4，不能启动 dataset v2 或训练。** 本文落实 [C4 事后失败诊断](c4-posthoc-failure-diagnosis.md)提出的“先统一输入/输出契约”前置工作，不重写已冻结实验结果。

契约 ID：`qwen25-single-tool-two-stage-v2-candidate`。固定 tokenizer：`Qwen/Qwen2.5-Coder-7B-Instruct@c03e6d358207e414f1eca0bb1891e29f1db0e242`。当前公开 MCP 工具定义仍为 23 个；schema 的聚合 SHA-256 为 `151c5453bf92f83343e93e53013bfc8f3518e5b6a7e9e2fc49e97ba863b0637d`。这些标识仅用于候选验证，不替代未来实验的独立冻结清单。

## 统一输入与输出

| 阶段 | 训练/validation 与未来推理共同使用的输入 | 唯一允许的输出 | 执行权限 |
|---|---|---|---|
| 1. 选择 | 固定 selector system prompt、按工具名排序的 23 项简短目录、当前一步用户任务；**不传**完整工具 schema | 严格 JSON：`{"tool":"create_box"}`，且工具名必须在当前目录中；不明确时返回 `{"tool":null}` 交由控制器澄清 | 仅选择，不执行任何工具 |
| 2. 调用 | 固定 invocation system prompt、同一当前一步任务、**只传选中工具的完整原始 JSON Schema** | 恰好一个 Qwen `<tool_call>{"name":"…","arguments":{…}}</tool_call>`；允许模板终止 token | 仍需通过既有隐私、路由、工具许可和 Rhino 执行门禁 |

候选实现由 [纯渲染与解析模块](../training/tool_contract_candidate.py)提供。对每个阶段，训练样本与推理请求调用**同一个渲染函数**；训练只是在同一前缀后追加 assistant 标签。工具调用必须匹配选择结果，JSON 不得有重复键、非有限数、附加说明、第二个调用或未知顶层参数，参数必须通过该工具的完整 JSON Schema 校验。输出无效时拒绝执行，不猜测参数、不自动修复，也不回退到任意其他工具。多步任务需要在每个动作前重新选择；状态必须以有界的当前一步输入显式提供，不能偷偷把无限历史拼入提示。

隐私门、模型路由和工具执行授权仍在模型之外。selector 产生的工具名**不是**授权；不得因为“选中了工具”就跳过用户确认、强制本地或禁止云端降级规则。本模块未接入 live Agent、P2 推理服务、C2 validation 或正式训练入口，因而不会改变原实验口径。

## 是否现在建设 dataset v2？

**仍不启动。** CPU 检查证明“统一模板 + 完整单工具 schema”在合成的一步输入下可训练、可解析，并给出了明确的超长失败行为；它没有证明模型能正确选择工具、产生有效参数、完成真实 Rhino 闭环，或长期维持 2,048-token 预算。下一实验立项前至少需要：

1. 对新训练/validation 样本定义一动作一标签的 selector 和 invocation 双视图；每条记录同一当前步骤与必要的最小状态，不能在推理时使用训练标签来替模型选工具。
2. 在新实验 ID 下预注册 selector 正确率、合法参数率、真实闭环指标、隐私/确认门、失败处理、上下文预算和唯一超参数方案；准备**新的未见保留集**。已消费的 A5、已分析的 P2 不再作为调参用盲测。
3. 纯合成控制器已验证基本拒绝执行与路由边界；在任何 GPU 训练前，仍须证明真实用户确认、可信本地路由、Rhino 场景版本/持久幂等，并审查目标覆盖是否足以支撑 23 个工具，而非仅重复原 6 类调用。

所以当前结论是：**契约方案具备离线技术可行性，但 dataset v2 的数据、控制器和评测门尚未就绪；继续使用已验证的混合路由。**
