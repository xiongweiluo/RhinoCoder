# C5 模型桥 B：真实模型／Rhino 开发工程门

2026-10-03，仓库所有者对[新 B 开发 spec](../eval/c5/modelbridge-development-spec-20261003-b.json) `be91b9b3…537de9` 和[完整 runtime freeze](../eval/c5/modelbridge-runtime-freeze-20261003-b.json) `686c3a1c…7e54b4` 作出直接批准。B 与首槽失败且已[退休的 A](c5-modelbridge-development-failure.md)使用不同 ID、私有状态、远端部署与永久 claim；A 未重跑。双 CI、Mac/远端源码和实际导入闭包、原基座及 checkpoint132、GPU 空闲与租期边界在 B admission 前复核一致。

B 的固定八槽在 Rhino 8 的独立未保存 headless 毫米夹具中单次完成，基座与 LoRA 各经历写入、只读、澄清和不支持操作。远端同一模型会话处理 8 个请求、共 11 次双阶段生成；Mac 收到原始输出后才进行真实夹具读回和签名许可，Rhino 原生门仅执行通过严格契约且被槽位政策允许的输出。所有槽都有独立 `close`／实际删钥／`stop`，最终 hub 无失败地停止；九份临时密钥均核实不存在。远端 worker 退出码 0、资源结算与 42 份只读导出记录一致，正式 holdout 读取、训练调用均为 0。

独立联合审计核对原始 Mac/远端模型请求与阶段回执、永久 claim、场景绑定、许可与两份 SQLite 账本、原生立即/稳定回执、几何及只读语义、生命周期和资源。结果为 [**C5 开发工程兼容性门通过**](../eval/c5/modelbridge-development-audit-20261003-b.json)：八槽全部可分类，1 次实际写入和 1 次实际只读均来自未修复的 LoRA 输出，写入几何/只读结果通过；操作性错误、重复或额外派发、未核实清理均为 0。含加载与空闲 GPU 时间 322.413 秒，加上退休 A 的 17.614 秒，总计约 340.027 秒，低于原开发配额 3600 秒；结束后 RTX3090 为 11 MiB／0%。

这**不是模型质量门全部通过**。八个开发槽中 LoRA 写、读、澄清、拒绝共 4/4 语义通过；基座写、读、澄清失败，仅不支持操作 1/4 通过。基座写入为 selector 契约失败，基座只读为 invocation 契约失败，均安全零派发；不得通过提示词修补、解析修复或重试追认成功。八槽是协议与安全兼容性烟测，样本极小且为公开开发题，不得外推真实 Rhino 总体成功率，也不得把“LoRA 开发题优于基座”直接写成最终 C5 GO。

现在才允许准备真正新的、预注册的20个任务家族。它们必须排除训练、验证、开发、A5/P2、R 已消费任务，以及由独立保管人私下核对的原 C5 80 家族；开发代理不得读取原80正文。全新20题的身份、排序、评分器、模型／执行器源码、剩余正式≤3 GPU-hours及失败停止规则须先冻结，再取得仓库所有者对**新的**正式 spec/runtime 的明确批准。正式门槛仍为 LoRA≥14/20、相对基座≥15pp且配对净胜≥3，关键安全违规、重复写和未核实清理均为0；不可因本次开发结果降低。即使正式 GO，也只授权后续产品接入验证，不自动切换默认混合路由或合并 PR。
