# 双阶段工具控制器：CPU 合成安全审计

日期：2026-09-21。状态：**候选控制流程通过合成测试；未接入真实模型、Rhino、产品路由或新实验。** 本文延续[工具调用候选契约](tool-call-contract-v2-candidate.md)，仅验证在模型输出可能错误、场景可能并发变化时，控制器是否会拒绝危险动作。C0–C4 的 `NO-GO` 与混合路由部署保持不变。

## 控制顺序

独立[候选控制器](../training/tool_controller_candidate.py)每次只处理**一个**当前动作：获取场景快照 → 检查后端/执行器为合成环境并执行隐私前置判断 → 选择工具或澄清 → 再次核对场景快照 → 检查写操作确认 → 用所选工具的完整 schema 生成并校验调用 → 第三次核对场景快照 → 至多一次合成执行 → 核对执行回执和新场景版本。它没有自动 fallback、无效输出修复、截断或重试。下一个动作必须重新读取场景。

场景快照包含单调 revision、由外部场景提供者给出的 SHA-256 和有界 JSON 摘要；摘要只能用合成别名，原始 Rhino GUID 被拒绝。相同的任务与快照会进入两次模型提示；任何中途版本或内容变化都中止执行。写工具默认需要**外部提供**、绑定任务哈希、工具名、scene revision 和 scene SHA-256 的确认对象；模型的选择本身不是批准。这里验证的是绑定和门禁逻辑，**不声称已实现真实用户确认**。

## 合成验收结果

命令：

```bash
python tools/audit_tool_contract_candidate.py
python -m pytest -q eval/test_tool_controller_candidate.py
```

| 情境 | 验收行为 |
|---|---|
| 合法只读调用 | 两阶段各一次，合成执行一次；场景版本不变 |
| 模型返回 `{"tool":null}` | 请求澄清，不进入调用或执行阶段 |
| 写工具无确认、确认绑定了别的任务/工具/场景 | 请求确认，零次执行 |
| Critical 注入/密钥请求、场景摘要中的提示注入或隐私分类器故障 | 隐私门在模型前阻断或拒绝；零次模型/执行器调用 |
| 云后端或非合成执行器 | 即使任务低风险也在前置阶段拒绝；不改现有混合路由 |
| 工具名、参数、标签结构或模型服务错误 | 无效结果/服务错误终止；零次执行 |
| 选择后或调用后场景被并发修改 | 快照漂移终止；零次执行 |
| 过长任务/场景、原始 GUID | 拒绝输入；不截断、不调用模型 |
| 执行回执丢失或与场景不一致 | 标为执行结果不确定，不自动重试；同一进程/快照阻止重复派发 |
| 一次成功写入后的下一动作 | 从新的场景 revision 与摘要重新构造提示，不复用旧状态 |

固定 tokenizer 的有界合成场景核查：selector 提示 **332 token**；逐一附带 23 个工具中的一个完整 schema，最坏提示 **1,178 token**，在 2,048-token 上限下仍预留 512 token。控制器专项 **14 项测试通过**；这些数字不等于模型正确率或真实 Rhino 通过率。测试和审计不读取 A5 holdout、P2 原始任务，不调用 GPU、真实模型或 Rhino。

## 不能据此立项 dataset v2 的剩余门槛

1. 合成后端的 `synthetic-local` 标记与合成执行器的 `synthetic_only` 标记**不是生产级身份验证**。真实接入须由可信路由适配器证明本地性、延续既有隐私/最小化策略；不能用本原型替换已验证的混合路由。
2. 当前确认对象只测试任务/场景绑定；尚无真实 UI 人工确认、撤销或持久审计。实际 Rhino 执行器也尚未验证原子 scene revision 检查和跨进程持久幂等。回执不确定时必须人工查场景，不能自动重放。
3. 两阶段选择器没有真实模型推理结果；工具选择准确率、参数合法率、多步闭环、澄清质量、长任务/大场景覆盖与失败恢复均未知。候选目录描述是否足够区分相近工具，也未通过新数据验证。
4. 若将来启动新实验，必须新实验 ID、新预注册、新 train/validation 与新的未见保留集；已消费的 A5 和已分析的 P2 不能再用作挑方案的盲测。先给出 selector/调用器的独立质量门和安全门，再决定是否投入 dataset v2 或 GPU。

**决策：合成控制流程具备继续设计的基础，但仍不启动 dataset v2、训练或产品切换。**
