## 已确认的三处工程机制

| 环节 | 已证实事实 | 最小修复及反证 |
| --- | --- | --- |
| D1 资产预检 | 16个资产的SHA全部匹配；14个基座snapshot文件均为指向缓存blob的符号链接。首个`resolve()==path`谓词直接拒绝，错误文字不能解释为权重损坏 | 在修订包中逐文件冻结逻辑路径、实际目标和原SHA；两者及元数据持续核对。允许已登记链接，拒绝未登记目标、同字节换目标、目标字节变化和检查后替换；不改模型资产 |
| D2 启动结算 | GPU已返回终止结算，Mac把它作为不符合ready的响应抛错，未保留到`gpu`字段，原结果仍为null | 先永久记录启动响应并核对包身份；终止结算保留、避免向已退出进程再发stop；已核实停止则继续原导出，未知仍未知。CPU入口回归覆盖两种终止状态 |
| D3 导出核对 | 冻结导出比较整个stat，其中atime可因读取变化；只读取回时6个文件出现仅访问时间变化，内容和dev/inode/size/mtime/ctime均稳定 | 用不跟随链接的文件描述符读取，前后核对内容相关身份，排除atime；保留内容变化、替换与符号链接拒绝，不跳过成员hash验证 |

被冻结的导出产生4096字节不完整archive，原件及stderr保留。随后在已经停止的**本批新目录**内，只读取回白名单15文件、12,938字节，逐项核对hash；原`development-result.json`没有改写。补充审核将原Mac的`gpu=null`与完整GPU停止证据并列保存。未读取历史私题、答案、训练记录或模型原始日志。
