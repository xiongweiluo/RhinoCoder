## 三个核心场景

1. 单对象属性：在不同坐标创建半径 12 的青色球体，检查中心、24×24×24 尺寸和颜色。
2. 多对象与群组：创建 3 根半径 5、高 20 的黄色圆柱并分组，检查数量、中心、10×10×20 尺寸、颜色和群组名。

为避免九次运行互相覆盖，各次任务使用不同的 X/Y 偏移；尺寸、属性和空间关系保持一致。

## 真实验收中发现并修复的问题

1. 旧 UI 进程导致健康接口仍使用旧版 Rhino 响应解析。终止旧进程并由 `./scripts/start.sh` 启动当前代码后，嵌套 Rhino 状态正常显示。
2. 任务完成后 Recent Runs 不实时刷新。服务端新增 `history.updated` 广播，前端即时消费。
3. 指标卡缺少缓存拆分和精确/估算成本状态。UI 已补充命中、未命中 token，并按计价状态显示“精确成本”或“估算成本”。
4. Scene Summary 对象卡未展示群组。对象卡已显示一个或多个群组名。
5. 点击历史任务只能切换 ID，无法恢复旧事件。历史快照现包含该次运行事件，点击后可恢复 Tool Trace、Scene Summary 和指标。

## 历史回看回归验证

重启当前服务后连续完成两次补充任务：最新任务有 7 条事件；点击上一条历史记录后，UI 恢复该任务的 15 条事件、14,629 ms、4 轮、4 次工具调用、56,203 token、52,608 / 2,755 缓存拆分、$0.002120 精确成本，并恢复中心 (700,0,0)、尺寸 12×12×12 的球体场景结果。
