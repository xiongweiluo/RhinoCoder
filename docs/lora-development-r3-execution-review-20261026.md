## 这次准备已验证什么

- R3 的两个前批记录分别绑定 R1/R2 完整包、原公开审核 hash、精确 source/state；不可漏批、调换、重复、改写消费或替换旧路径。宿主只接受与这些身份相符且 stopped、无当前夹具、回调已移除、密钥缺席的旧对象。对其他或未收尾会话拒绝，不全局清除。当前宿主实际对象集合仍由获准入口核对，本次没有进入 Rhino。
- 已补齐 D4 两个公开源码依赖；helper 解析前移到 GPU 预检/模型导入前。部署包 CPU 检查包含 GPU/Mac/Rhino/wrapper 模块的惰性导入，禁止模型/Rhino 后端和 live 入口调用。新临时 bytecode 前缀与 `-I -S -B` 禁止依赖旧 pyc 或完整仓库回退。
- 两端各291个准备文件（289源码/公开配置＋包＋Mac环境）逐字节一致。实际 Mac Python3.13.5、目标 Linux Python3.11.17 都从部署包通过隔离导入：各54个公开源码来源，Mac39/Linux40个已有CPU依赖来源，模型后端导入0。未安装包。
- [目标服务器只读预检](../eval/lora-development/readonly-preflight-r3-20261026.json)22.340秒通过：硬件、24,298项环境文件的原指纹、16个固定模型资产、链接绑定及后续元数据检查；两前批源码/终止结算一致，新state不存在。剩余磁盘约64GiB。新SSH控制连接已由所有者恢复，仅读写公开准备文件及核对先前获准的新开发结算。
- [准备与回归记录](../eval/lora-development/preparation-r3-20261026.json)：104项不同的相关CPU检查通过，覆盖双前批、旧批准拒绝、累计预算、逐个宿主退役条件及导入遗漏；三条导入检查因加强bytecode隔离复验，合计107次通过。Rhino侧新增代码通过Python3.9语法解析。既有tokenizer/提示词、无关实现和历史验证复用。

这些证据不证明实际模型 backend ABI、权重加载/生成、原生任务成功、历史家族独立性或整个 Rhino 宿主字节闭包。未知保持；不会要求所有者补查历史私有材料来换取继续研究。公共执行源码、权重/评分身份及新包须在批准后再次核对字节；精确提交的 CI 必须全部通过，旧提交通过不能替代。

## 批准后持续推进到第一阶段终点

收到本包精确批准且 CI 成功后，按原32槽连续开发、收尾、审核、统计；不再逐命令索要权限。若 S/A 结果不足或反馈未改善，保留 original/证据不足，不追加候选或补槽。原20题及所有公开开发家族继续排除最终集。

随后在同一主任务内完成：系统选择与适用范围说明、公开覆盖审计与训练/不训练决定、最终参评身份和共同链/评分实现、最终N/统计/资源/停止规则及完整比较准备包。没有具体训练依据则基座＋当前LoRA两路，不增加epoch、不制造adapter。若出现训练依据，只提交一次候选训练所需的具体数据/validation/预算集中审批，不借本包执行。

本包只验证读取进度、澄清/拒绝的窄范围。不能把32槽完成当作写入、全部12工具、恢复机制或产品可靠性均已验证。最终适用范围须由真实结果支持；若最终比较确实需要尚未覆盖的原生操作，先列出具体缺口和最小额外开发范围集中处理，不把完整UI、独立R草稿或所有历史未知自动加入依赖。

统计规模沿[事前设计补充](lora-final-comparison-stat-design-20261026.md)：40家族和原预算仍是草案，不能预设足以确认10个百分点提升；真实开发时延用于可行性，开发成绩不能用于反向选最终题目。最终方案选择全固定后才进入第二阶段独立保管，不在本次生成或消费最终测试集。

第一阶段标准不变：必要真实开发及优化/保留现状决定完成、关键执行缺口有处置、训练分支明确、最终比较方案可冻结。设计、CI、PR或正向成绩均不单独构成完成。原C4/C5 NO-GO、历史失败/消费/未知、审核限制和默认混合路线保持。
