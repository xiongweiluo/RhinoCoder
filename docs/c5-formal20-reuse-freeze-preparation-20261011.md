## 3. 最小CPU/合成验收包（下一阶段实现要求）

- 新旧study/grant/spec/runtime、目录与消息身份交叉负控；旧claim保留，新状态不得指向旧源/state。
- 所有传递公共文件缺一、symlink/内容/导入漂移及实际部署根预检；冻结前不能由builder自报成功替代独立核对。
- 启动前后、bootstrap中、请求持久化前后、发送后/回执前、export/stop期间的断开与进程死亡；区分发生、已确认和未知，未知不再发送。
- 真正framed CPU子进程的半帧/EOF/重复/错误绑定/迟到，完整解码验收计时；保持strict parser原样，不把“重试成功”当工程成功。
- 模型侧请求/确认/生成及原生许可/派发计数的原始重建，篡改、缺日志与不完整coverage必须失败/未知，不能补零。
- 外部公开锚获取失败、source/host漂移、进程PID复用、epoch/monotonic偏离、容量/预算耗尽、清理未知均有fail-closed控制。
- 40槽纯合成签名/SQLite/几何替身联合复算；测试不使用真实20题的正文、ID、逐题哈希、答案或几何作为夹具。

本轮纯公开草案检查只能验证文档身份/旧证据/资源留空/门禁一致性，不是上述工程包、模型能力、真实Rhino或实际部署验收。

在本准备分支运行：

```sh
python tools/check_c5_formal20_reuse_draft.py
python -m pytest -q -p no:cacheprovider eval/test_c5_formal20_reuse_draft.py
```

检查器只读取固定的五份公开仓库JSON，无私有路径参数；不解密、不触碰旧state，不建立grant/claim/run，也不import模型/Rhino、连接GPU或调用准备器。输出必须为 `draft_boundaries_consistent_not_execution_authority`、`execution_ready=false`。它校验的是本准备快照；不能修改它来当正式运行器。
