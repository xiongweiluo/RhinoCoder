# 断线与故障恢复验收报告

验收日期：2026-08-27  
环境：macOS、Rhino 8、DeepSeek 兼容 API、React UI、aiohttp UI Server

## 验收结论

- WebSocket 在任务运行中断开并重连后，可按同一 `run_id` 恢复当前事件快照并继续完成任务。
- Rhino Listener 可热重启；无需重启 Agent/UI 即可开始新任务。
- 无效 GUID、空参数、LLM 超时和 MCP 子进程退出均有标准错误码、明确原因、恢复建议和 UI 重试入口。
- MCP 一次性退出后，从 UI 点击“重试任务”即可由同一服务启动新 MCP 子进程并恢复成功。
- 查询和变更请求均支持有限网络重试；变更请求的所有尝试复用同一幂等键，Listener 会缓存超时结果，避免重复入队和重复对象。
- 全量检查通过：53 项测试、30 条基准任务格式、密钥扫描和前端生产构建全部通过。

本轮断线和故障恢复验收通过。

## 真实环境演练

### WebSocket 断线恢复

1. 从 UI 启动三方块创建、着色、打组和场景核对任务。
2. 任务运行至第 2 个事件时刷新页面，使原 WebSocket 断开。
3. 新连接建立后立即恢复 2 个既有事件，任务未被取消或重新创建。
4. 任务最终以 `completed` 结束，共 26 个事件。
5. Scene Summary 显示 3 个 10×10×10 蓝色方块及群组 `断线恢复验收`。

### Rhino Listener 热重启

Listener 健康接口现返回 `instance_id` 和 `started_at`。连续两次启动脚本后：

- 重启前实例：`7eaef7cf…`，启动时间 `2026-08-27T09:51:00Z`。
- 重启后实例：`8064a50f…`，启动时间 `2026-08-27T09:51:30Z`。

实例标识和启动时间均发生变化，证明 Listener 已真实重启。Agent/UI 进程未重启，随后新任务以 15 个事件完成，并正确创建中心 (900,0,0)、尺寸 14×14×14、RGB(0,255,0) 的球体。

## 故障注入结果

| 故障 | 注入方式 | 结果 | UI 恢复表现 |
|---|---|---|---|
| 无效 GUID | `move_object` 使用 `not-a-guid` | `failed` / `http.invalid_argument`；路由层拒绝，未进入 Rhino 主线程 | 显示无效字段、修正建议和重试按钮 |
| 空参数 | `create_box({})` | `failed` / `tool.execution_failed`；明确列出 width、depth、height 缺失 | 显示参数校验明细和重试按钮 |
| LLM 超时 | 临时设置 1 ms 超时、0 SDK 重试 | `failed` / `llm.timeout`；仅 3 个事件，没有工具调用 | 明确说明本轮未执行新工具，可安全重试 |
| MCP 退出 | 临时 MCP 子进程在握手前退出 | `failed` / `mcp.process_exit` | 提示检查 MCP 日志，无需重启 UI |
| MCP 恢复 | 一次性退出后点击错误卡片中的“重试任务” | 第二次运行 `completed`，共 7 个事件 | 错误卡片自动消失，历史保留失败与成功两次运行 |

所有临时故障配置在验收后均已撤销，最终服务使用正常项目配置运行。

## 防重复对象机制

变更类 MCP 请求在首次发送前生成幂等键，网络层重试复用同一键。Listener 在主线程超时时会：

1. 将待执行工作标记为取消，Idle 回调会跳过它。
2. 缓存该幂等键对应的超时结果。
3. 对同键重试重放已有结果，不再次入队。

自动测试验证了第一次响应丢失后两次 HTTP 尝试使用相同 UUID，并验证 Listener 同键超时请求只进入队列一次。

## 本轮实现

- 为 `llm.timeout` 和 `mcp.process_exit` 增加独立、可恢复错误分类。
- 识别 FastMCP 文本帧中的业务失败，未恢复的工具错误会使任务正确进入 `run.failed`。
- 新增共享 GUID 校验，单对象 GUID 和纯 GUID 列表在进入 Rhino 主线程前验证。
- WebSocket 快照按当前运行优先恢复事件；已结束任务仍可从历史恢复。
- UI 新增错误恢复卡片、错误码、建议、重试按钮，以及 Tool Trace 失败详情。
- Listener 健康接口新增实例标识和启动时间。
- MCP 网络重试统一复用幂等键，Listener 超时响应进入幂等缓存。
